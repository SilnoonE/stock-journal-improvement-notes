# 주식매매노트 개선 기록

사용 중인 Android 앱을 개선하면서 문제 발견, 요구사항 정리, 구현, 재검토를 반복한 과정을 기록합니다. **개발 과정 문서와 일반화한 전후 코드 예제 저장소**입니다.

## 최신 기록 — 사용자 리뷰에 따른 수정

**[리뷰에서 시작한 PDF·실현손익·UI 개선 과정](REVIEW_DRIVEN_IMPROVEMENTS.md)** — 2026-09-23

PDF 생성 실패와 실현손익 표시 제보를 출발점으로, 첫 수정 후에도 기기에서 재발한 문제를 다시 점검한 과정을 정리했습니다. 이전 소스와 현재 구현을 비교한 설명, 일반화한 짧은 전후 코드, 수정 선택의 이유와 검증 범위를 함께 담았습니다.

- 보유 원금과 실현손익의 의미를 구분하고 화면 데이터 연결 수정
- PDF 생성·저장 분리, 입력 사본, 폰트 및 릴리스 설정 보강
- 투자 가이드 줄바꿈, 일부 다국어 문구, 거래 구분선 개선

원본 리뷰 이미지와 앱 전체 소스는 포함하지 않았습니다. 운영자의 해결 보고와 직접 확인한 코드 변경을 구분했습니다.

## 이전 기록의 범위 — 2026-09-15~16

2026년 9월 15~16일 진행한 작업을 정리했습니다. 기존 리뷰 관련 프로젝트와 별개의 기록입니다. 사용자 경험 개선과 기존 기록 보존을 함께 다뤘으며, 한 번의 구현으로 완료를 판단하지 않고 수정본을 반복 확인했습니다.

| 영역 | 개선 목적 | 진행 내용 |
|---|---|---|
| 투자 가이드 | 필요한 개념을 쉽게 찾기 | 추천·사전·저장 구성, 한글 중심 제목, 예시·주의점·관련 개념 배치 |
| 데이터 관리 | 기록을 옮기고 보관하기 | 전체 백업과 CSV 용도 분리, 복원 선택과 오류 안내 개선 |
| 보고서 | 기간에 맞는 실적 제공 | 원가 계산에 필요한 이력과 표시 기간 분리, 요약·차트 비교 |
| 홈 | 긴 거래 목록의 부담 줄이기 | 최근 10건, 접기·펼치기, 전체 거래 이동 |
| 편집 | 수정하지 않은 정보 유지 | 편집 대상과 보존 대상을 구분하고 검토 |

## 작업 방식

1. 사용자가 실제로 불편한 지점을 설명하고 우선순위를 정했습니다.
2. Codex가 소스를 검토하고 변경 요구사항과 확인 사례를 정리했습니다.
3. Android Studio AI를 통해 구현을 진행했습니다.
4. 완료 보고만 믿지 않고 변경된 코드를 다시 읽었습니다.
5. 누락·회귀·표시와 계산의 불일치를 찾으면 후속 요청으로 범위를 좁혔습니다.
6. 빌드 결과, 계산 검증, 기기 검증을 서로 구분해 기록했습니다.

## 무엇을 배웠나

- 화면 개선과 데이터 보존은 함께 설계해야 합니다.
- 목록을 짧게 보여주는 변경이 통계의 입력 데이터까지 줄여서는 안 됩니다.
- 과거 거래가 현재 기간의 매도 원가 계산에 필요할 수 있습니다.
- 같은 내용의 기록이 반드시 같은 거래는 아닙니다.
- 저장 요청과 저장 완료는 다릅니다.
- 백업 파일 생성뿐 아니라 실제 복원 결과를 확인해야 합니다.
- 기존 콘텐츠를 개편할 때 저장된 항목과 연결 관계도 확인해야 합니다.
- AI의 완료 보고와 직접 실행한 검증은 구분해야 합니다.

## 이전 작업의 검증 상태 — 2026-09-15~16

대화 중 수정본에서 디버그 빌드와 기존 기본 단위 테스트가 통과했습니다. 별도 계산 검사에서 간단한 매매 손익·수익률, 기간 밖 배당 제외, 가이드 연결 유효성을 확인했습니다.

기존 기본 단위 테스트만으로 전체 기능을 보장할 수는 없습니다. 실제 기기의 업데이트 설치, 백업 왕복 비교, 중단·재시작 시나리오는 추가 검증 대상입니다. 이 문서는 배포 완료 선언이나 모든 오류가 해결됐다는 보증이 아닙니다. 결과는 해당 시점의 검사 범위에 한정됩니다.
