# 제작 과정과 차트 문제 해결

기록일: 2026-09-28 · Y Labs

## 1. 목표

주식매매노트 Android 앱을 소개하고, 사용자가 앱 백업을 PC로 옮겨 큰 화면에서 거래를 복기할 수 있게 하는 것이 목표였습니다. 기존 Kotlin 앱의 거래 모델과 JSON 형식을 확인한 뒤 웹 화면을 설계했습니다.

## 2. 구조

```text
Android 앱 -> 사용자가 백업 ZIP 내보내기
                          |
                          v
                   웹에서 파일 선택
                          |
                          v
           브라우저: ZIP 해제 -> JSON 읽기
                          |
                          v
                   집계 -> 카드·차트·표
```

현재 운영 사이트는 정적 HTML·CSS·JavaScript로 구성했습니다. React나 별도 데이터베이스는 사용하지 않았습니다. Python은 로컬 미리보기, Node.js는 개발 검증·게시 보조에 사용했으며 웹의 거래 계산은 브라우저 JavaScript가 수행합니다.

## 3. 구현 순서

1. 앱 소개와 백업 분석이라는 두 가지 흐름을 정했습니다.
2. 앱의 거래 필드와 백업 JSON 파일 구성을 확인했습니다.
3. 앱 분위기에 맞는 파란색·남색, 카드, 실제 앱 화면을 배치했습니다.
4. JSZip으로 파일을 읽고 거래를 집계해 결과에 연결했습니다.
5. 가상 거래로 계산값을 검산하고 로컬 브라우저에서 파일 입력을 확인했습니다.
6. 정적 파일을 호스팅에 게시했습니다.
7. 등록대행사에서 구입한 도메인을 호스팅에 등록하고, 안내받은 DNS 값을 입력했습니다.
8. DNS 조회·HTTPS 상태·실제 주소 접속을 차례로 확인했습니다.

## 4. 사용자 피드백: 차트가 보이지 않음

처음에는 결과 영역이 `display: none`인 상태에서 Canvas 너비를 측정했습니다. 숫자와 표는 이후 표시됐지만, 너비 0으로 그린 차트는 보이지 않았습니다.

```js
// 문제: 아직 숨겨진 영역의 크기를 측정한다.
drawChart();
dashboard.classList.add('active');

// 수정: 영역을 표시한 다음 프레임에 측정하고 그린다.
dashboard.classList.add('active');
requestAnimationFrame(drawChart);
```

창 크기 변경에도 대응하도록 ResizeObserver를 연결했습니다. 데이터가 한 달뿐인 경우에도 표시가 남도록 처리했습니다. 공개 예제에서는 같은 표시 순서를 막대 차트로 보여줍니다.

## 5. 검증한 가상 계산

100원에 10주 매수(수수료 2원), 150원에 4주 매도(수수료 3원), 배당 20원(세금 2원), 별도 세금 10원인 가상 사례를 확인했습니다.

- 실현손익: `(150 - 100) × 4 = 200원`
- 총 비용: `2 + 3 + 2 + 10 = 17원`
- 순손익: `200 + 20 - 17 = 203원`
- 남은 보유 수량 6주, 원가 600원

이는 운영 계산을 확인한 하나의 테스트 사례이며 모든 거래 유형 검증을 의미하지 않습니다. 공개 예제의 테스트는 월별 합산·입력 형식·빈 데이터만 검증합니다.

## 6. 현재 한계

- 보유 비중은 매입 원가 기준이며 현재 시세·평가손익이 아닙니다.
- 운영 사이트는 백업 설정 환율 하나를 달러 기록에 적용하므로 거래별 환율 기준 집계와 차이가 날 수 있습니다.
- 현재 운영 사이트의 ZIP 체크섬 검증, 파일 크기 제한, 입력 필드 검증은 추가 개선할 영역입니다.
- 서버 계정 저장과 자동 동기화는 구현하지 않았습니다.
- 공개 예제는 ZIP 대신 합성된 월별 손익 JSON만 받습니다.

## 7. 배운 점

화면을 먼저 표시하고 크기를 측정해야 하며, “파일을 읽었다”와 “계산이 정확하다”는 따로 확인해야 합니다. 도메인 결제, DNS 설정, 인증서 발급, 사이트 배포도 서로 다른 단계입니다. 다음에는 앱과 웹의 계산 규칙을 더 명확히 맞추고 경계 사례 테스트를 늘릴 계획입니다.
